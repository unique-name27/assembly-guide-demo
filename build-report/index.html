Assembly Guide Build Report

A browser tool that takes a STEP CAD file and an instructions file, blows a server-style assembly apart so people can see where each part goes, then walks them through putting it together.

Try the stand-in demo: unique-name27.github.io/assembly-guide-demo. It uses an invented 4U server, not a real product.

1Convert once, on your PC

A Python script reads the STEP file and walks its assembly tree. It turns each unique part shape into triangles once and saves its progress, so a long run can be stopped and resumed. A second script shrinks and compresses the shapes. The result is three files:

  • model.glb holds only the unique shapes.
  • parts.json gives every part's id, name, part number, position, colour, kind (sheet metal, board, fastener, cable, module) and the direction it pulls out.
  • _report.json says pass, warn or fail in plain words. A fail blocks publishing.

Part ids come from the part's place in the tree, not its name, because CAD names are often missing or repeated.

2The guide file

guide.json sits beside the model and lists the steps: which parts, how many, how they move in, the tool, the torque, warnings, checks, the camera view and cable routes. It records which model it was written against. When the CAD is revised, the tool lists the steps that no longer match, and nothing is silently re-pointed.

3The viewer

A static web page with three layers:

  • The engine draws the parts with three.js. It stops drawing when nothing moves, so an idle page costs nothing.
  • The player works out where every part is for any step and any moment of that step. Because position is a pure calculation, scrubbing, going back, replay, reduced motion and repeatable screenshots all come from the same code.
  • The interface is ordinary page elements beside the picture, so everything works by keyboard alone.

4What the person sees

  • Blow-up. The model opens assembled, then comes apart in layers. A slider scrubs it.
  • Each step. The warning and the torque show before anything moves. The piece is highlighted, a dashed frame marks where it goes, and it travels in along its real direction.
  • Cables. A cable is drawn along its route with both ends named. It is never flown in as a rigid block.
  • Finding a part. A kit list with pictures, a search, and clicking a part.
  • Sharing and finishing. Every step has its own link and QR code. There is a print page, and a finished-build summary that repeats every torque value.

5Write the steps

You load a step spreadsheet, a parts list or a Word procedure. Each row is matched to CAD parts by part number first, then by name. Sure matches are accepted, unsure ones ask you, and nothing is guessed silently. Torque values are read by strict rules that ask whenever the text is unclear. The draft stays in your browser, and nothing you load leaves it.

6Publishing

One command publishes the stand-in to the public demo. Real CAD and real guides live in a folder that version control ignores, and a guard refuses to publish them to a public address.

7How it was checked

Unit tests cover the logic. A screenshot harness drives the real page in a headless browser and fails on any console error. Accessibility was treated as a requirement: keyboard-only use, large targets, reduced motion, and nothing said by colour alone.

Not done yet

  • The owner's real STEP file has not been run through the tool. The stand-in and a public test file have.
  • Real guides need a host with access control before they can be shared.
  • Nobody has listened to the sounds, printed the steps on paper, or opened the demo on a real phone.
  • A CAD file with thousands of parts has not been tried, and "Write the steps" has not been run on a real model.
  • Nothing was checked on a high-resolution (2x or 3x) screen.
